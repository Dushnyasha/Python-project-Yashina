# Как настроить правила

Откройте **Правила**, измените нужные значения и нажмите **Сохранить**.
Если есть ошибка, программа покажет её и оставит старые настройки.

В окне есть пять разделов, сохраняйте их все.
Текст пишите в двойных кавычках, элементы разделяйте запятыми.
После последнего элемента запятая не нужна. Дроби пишите через точку.
Комментарии внутри JSON писать нельзя.

Примеры ниже показывают отдельные части настроек, это не весь текст окна.

## Названия предметов, subject_aliases

У каждого предмета есть список названий из чата и листов ведомости:

```json
"Математика для анализа данных": ["математика", "матан", "математика для ад"]
```

Добавляйте варианты в список. Основное название предмета лучше не менять, по нему уже хранятся оценки и задачи. Регистр, ё/е и лишние пробелы не мешают поиску. Слишком общее слово вроде «анализ» может выбрать не тот предмет.

## Маркеры задания, task_markers

Это слова и фразы, по которым программа узнаёт задачу.
Например, добавьте `"эссе"` в существующий список, если в чате есть эссе.
Формы слов считаются отдельно, «сдать» и «сдайте» могут потребовать двух записей.
Маркеры пишутся обычным текстом, регулярные выражения не нужны.

## Маркеры срока, deadline_markers

Это слова вроде `"дедлайн"`, `"срок сдачи"`, `"до"`, `"к"`.
Можно добавить свою фразу, например `"последний день сдачи"`.
За «до» и «к» должна идти дата или день, «до сих пор» не подходит.

Для задачи нужны маркер задания, маркер срока и понятная дата.
Программа понимает:

- `05.10`, `05.10.2026`, `05/10`, `5 октября 2026`
- `сегодня`, `завтра`, `послезавтра` относительно даты сообщения
- `до понедельника`, `к пятнице`, ближайший такой день, включая день сообщения

Год берётся из сообщения или заголовка месяца в расписании.
В декабре январь и февраль относятся к следующему году.
Если год неоткуда взять, программа не придумывает его.
Новый маркер не добавляет новый формат даты, например «через неделю» потребует изменения кода.

## Исключения, exclude_markers

Сообщения с этими фразами пропускаются. Например, `"разбор дз"` или `"результаты проверки"`. Исключения важнее остальных маркеров.
Не добавляйте слишком общие слова, иначе можно пропустить нужные задания.
По умолчанию также пропускаются вопросы с «подскажите, пожалуйста» и обсуждения прошлых сроков с «можно было прислать».
Если нужное объявление содержит такую фразу, удалите её из исключений и импортируйте его снова.

## Веса оценок, weights

Внутри каждого предмета записаны работы и их веса:

```json
"Программирование на Python": {
  "ДЗ 1": 0.15,
  "ДЗ 2": 0.15,
  "ДЗ 3": 0.15,
  "Проект": 0.20,
  "Экзамен": 0.35
}
```

Вклад работы считается как оценка × вес. Названия работ должны совпадать с импортируемыми, например «ДЗ 1», «Лабораторная 1», «Контрольная 1».
Если сумма весов отличается от 1, программа предупредит и не изменит их сама.
Сейчас у математики сумма 1,002, её нужно уточнить у преподавателя.
Для семинара наставника отдельно проверяются три ДЗ с оценкой от 4 из четырёх, изменение весов не меняет это условие.

## Как проверить изменение

Сохраните правила и повторно импортируйте нужный экспорт.
Проверьте дату, предмет, источник и статус задачи.
Новые маркеры действуют при следующем импорте, старые задачи не удаляются.
Новые веса сразу меняют расчёт оценок.

ФИО, ссылки на таблицы, название чата и синхронизация при запуске настраиваются отдельно, через **ФИО и источники**. Оценки разных ФИО хранятся отдельно.
